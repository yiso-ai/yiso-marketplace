# 持久化、并发与恢复

## 当前数据库权威

新数据库实例使用本人独立配置/权限。已经D1-only的实例先核真实authority、epoch、config/head和已安装运行包身份；旧Page、Space账本及旧站只读保留，不能双写、回切或拿旧备份覆盖新head。读取不完整、missing config、未知版本不能初始化空状态。

技能更新与生产运行隔离：在独立Git worktree编辑、测试技能；不改固定runner源码包、配置、marker、锁或自动任务。技能文本/合成starter更新不等于升级已安装writer；需要修改生产writer时另做版本锁、恢复、并发测试和授权切换。不得让运行中的任务热加载未审核脚本。

## 受控提交

1. 持久保存batch/run ID、来源账号与namespace、当前body和source哈希、语义审阅、显式主归属、拟变更、覆盖关系、未决恢复义务及可恢复快照。
2. 依当前协议条件认领并读回writer/lease，验证epoch/config/version，其他有效writer存在则退出或核其同一run；不因超时或HTTP500删锁。只能释放自己本批次锁。
3. 在受控事务写canonical memo/body/revision、来源、分类、已核关联、原生表格、处理/覆盖账本、索引。多chunk时逐块回执与hash核验，全部完成之前不推进完成head。
4. 逐项读回正文/日期/机构、主归属、引用证据、双向关系、分页/目录计数及实际hash，保存真实回执；完成run/cursor/head后才称提交成功并更新成功时间。
5. 冲突或未知先核同一run/receipt/head与实际数据；旧请求不得换ID盲重放。单件来源故障隔离并持久保留gap，不用假终态让游标越过缺口。跨轮携带恢复义务。

来源扫描与归档完成各自记录完整性；已完整扫描范围可前移但未决义务必须持久且后续读回。账户错误、缺完整分页或全局证据不可信整轮停；独立已核材料可继续，不由无关未知记录永久封死所有来源。具体窗口/重叠/回查频率由本人项目配置，不复制原实例日期。

## 前端和源码发布

前端直接读同一D1，普通归档不为了同步网页额外扫描或部署。保持实际权限和全部获授权viewer，不修改受众硬过owner-private检查。源码修改需要时遵循当前官方Sites流程和项目规则，先核远端最新源码，push精确来源commit，再build/package/save/deploy并核结果；源码升级不是数据迁移授权。

展示成功时间必须对应已验实际提交，不使用启动或失败时间。站点失败不能重放数据库业务写入。区分本地测试、线上API、本人登录、匿名权限与视觉检查。

## 旧Page实例

如果用户尚未迁移，先制定迁移计划，未获切换授权时不把新协议应用到旧writer。旧项目只按其真实已批准协议维护；旧兼容 validate_batch.py 只检查其Page格式，不证明持锁/权限/真伪。迁移按 acceptance.md 完整验收后再换唯一权威，不以技能升级自动改变旧项目。
