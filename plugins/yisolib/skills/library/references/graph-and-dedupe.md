# 实体、双向关系、覆盖去重

## 实体与检索
公司目录维护稳定内部 ID、正式名、别名、已核实代码/交易所、页面 ID 与关键词；同名、品牌/母子公司、集团/上市子公司要分别核实。主题目录有稳定 ID、名称、范围。后台索引按公司、季度/期间、事件类型、机构及原作者检索。不得为了导航新增永久新闻监测公司。

## 按段落选主题

简报中独立的研究事项分别成篇，每篇单独选主公司或主主题。多个公司围绕同一行业问题提供证据时可以同篇，另建有依据的公司关联。题材相近、同一公司或同一邮件本身不足以把彼此独立的问题合成一篇。归属引文及其偏移指向库内 Memo 正文，无需记录它在简报中的位置。

- 读完整篇，再看每个有实质内容的段落能回答什么研究问题。产品机制、客户验证、出货、盈利影响、有依据的预测或反证都可能值得单独检索。综合纪要可关联多个主题，分别找支持各主题的证据。目录、议程、同业举例里顺带出现的词只作检索线索。
- 用规范名、别名或熟悉的上级主题查当前目录。命中宽主题时，用 `subjects "主题名或 ID" --children` 对照它和直接子主题的范围，必要时用子主题 ID 再往下查。专业缩写未命中时，结合原文产品用途查相应大类。中英文别名复用同一主题 ID，导航分组只用于找下级。
- 选择引文能直接支持的最具体主题。只讨论整体改造或行业需求，就保留有依据的大类。父子两级同时挂签时，父主题须有超出子主题的实质论述。并列主题各凭原文判断。例如，数据中心冷板通过客户验证，足以标“液冷”，理由中保留验证阶段。若只披露机房供配电与散热的整体预算，则标“数据中心电力与散热”。
- 准备批次前对照原文复核。值得按主题检索的段落应能从所选主题找回，每个所选主题也应能指回具体引文。仅有公司层面信息的 Memo 可以只归公司。在 `themes[]` 按 ID 去重，保留理由、当前正文原句和位置。多公司材料核对说的是哪家公司，预测、否认和已发生事项保留各自口径。纯图片证据按[图片规则](images.md)绑定。目录确有缺项时，在本次审阅中注明缺少的主题及对应原文。

## 有证据的双向关系
只从实质业务、产品、产业链、客户/供应商、竞争或研究论点建立边。边保存公司 ID、主题 ID、关系类型、证据材料 ID/选段、简短理由、事实/来源观点/待核推断标签。不能只靠名字或关键词共现。

已核实事实和有明确归属的来源观点可以展示；待核推断只后台。公司关联研究指向主题，主题关联公司指回公司，理由一致且可追溯。只导航或简短说明，不把其他公司完整正文搬来复制。不要把行业TAM当公司订单、接触当合同、技术可行当收入。

验收：双方端点存在，导航正确，双向边一致、无重复，证据材料存在，旧链接未破坏；材料多公司拆分仍保留正确正文归属。

## 去重与晚到材料
以原材料稳定 ID、内容哈希和公司/期间/事件身份建立去重，不用可变展示标题作唯一键。重复转发、同报告改文件名、同事实多个报道合并覆盖关系，但保留来源证据。

已有内部分析覆盖的卖方/公告/电话会/新闻不重复展示，只纳入重要新增数字、修订、不同观点或反证。不得因属于同季度/事件一律删掉增量。后到内部替代旧重复展示，先存可恢复快照与覆盖说明，再替换、读回；不破坏原证据或机构索引。无法确认重复的条目留后台待判断，不强行吞并。
