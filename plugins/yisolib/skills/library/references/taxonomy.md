# 动态主题目录与归档分类

## 先读取当前规范
从同一当前数据库head读取完整主题规范、目录、材料、已核关系与处理账本；目录是注册表的展示，不把技能内例子或旧缓存当静态白名单。缺失或冲突先查既有项目并核实，不另建平行注册表。遵守既有来源、编辑、权限和单写者规则；本流程不授权批量历史重分类、回灌或重启任何已暂停来源/任务。

以尽量覆盖常用研究主题为目标，把同花顺等分类仅作参考，不强制照搬；删除不合理类别、改善名称，按实际研究范围建立层级。不要把外部分类名或其成分股直接当研究关联证据。

## 名称、范围与关系
- 选最清楚、通用的中文或英文规范展示名；按需要保留另一语言名称与常见别名。名称变化不改变既有稳定主题 ID、Page URL 或历史。
- 仅合并指向同一研究范围的真正同义叫法。相关概念、宽窄概念、同名异义不可并作同义词。已有不同 ID 的合并须保留旧 ID 映射、历史及旧链接可达性，不直接删除历史或断链。
- 对通用或多义别名，结合上下文、行业、实体与来源正文消歧；歧义未解留待核，不以关键词自动映射。
- 父子关系表达明确的范围收窄；跨领域相关性用独立交叉链接。导航使用一个可解释的主父节点，相关/跨行业关系单列；历史多父DAG可保留已审映射，不能自动压平或复制正文。禁止自指、悬空父节点和循环。
- 区域、政策、市场篮子和供应商/生态标签先识别为检索维度或标签；只有独立、清楚的研究范围才建为研究主题。标签命中本身不产生公司—主题边。

## 授权归档中的动态扩展
在已获授权的未来新材料归档中，若当前目录无法准确容纳实质研究，可按需要新建主题，无须把本轮目录视为定稿。先查规范名、别名、范围和近邻节点，确认确实缺项；不要为单个关键词建立重复或过细空主题。

遵循项目既有模式记录稳定 ID、节点类型、规范名、范围（必要时含排除项）、别名、父节点及独立交叉链接、创建/变更来源依据和状态。分类参考来源与材料关联证据分开保存于私有记录。实际公司/材料关联只能由实际来源正文中的实质证据支持，按 graph-and-dedupe.md 核验，不因新增主题或父子继承自动制造边。

仅用于分类覆盖的节点标明 taxonomy-only 或项目等价状态，不创建空研究档案，不计入材料数或已有研究页数。有实质正文或有证据导航需求才激活/复用数据库主题实体；navigation_group只作目录分组，不直接挂材料；导航只指向实际存在的实体。

## 同事务提交与展示
读取当前D1 head/authority/config，按既有协议认领单writer→保存计划/语义审阅/可恢复快照→验证稳定ID、别名冲突、主父与无环性、历史映射→按epoch/version条件提交主题与材料/关联/账本→逐字段读回。冲突重新读取合并，不用旧目录覆盖新增节点；未知先核同一回执，不能盲重试。

目录由当前数据库读取，不另建定时任务，不重建空状态或写旧Page。区分taxonomy_only、navigation_group、已激活研究档案和真实材料数；目录扩容不算新增研究。公司与主题边必须有当前正文证据，不自动从分类成分或父节点继承。

## 离线结构预检
运行 `python scripts/validate_taxonomy.py proposed.json previous.json`，两个文件均为从实际注册表转换的私有核验快照，不修改生产 schema。`nodes` 含 `id`、`canonical_name`、`aliases`（对象：`name`、可选 `context_only`）、`parents`（ID 数组）、可选 `page_id`/`page_url`；`crosslinks` 含 `source`/`target`；`company_ids` 和 `company_topic_edges`（`company`/`topic`）用于检查实际关联端点。主题 ID 使用字符串。

脚本检查 ID 唯一、父节点/关联端点存在、层级无环、规范名与别名分别按 NFKC/大小写/空格规范化后的冲突，以及旧 ID 和既有 Page 引用保留。规范名冲突须改为可区分名称；跨节点别名冲突须对相关别名标记 `context_only`，仍须人工逐件消歧。提供完整旧快照才能检查保留性；脚本不证明语义正确、证据真实、持锁、授权或远端写入成功。既有项目使用不同结构时做显式映射，不靠丢字段使预检通过。
