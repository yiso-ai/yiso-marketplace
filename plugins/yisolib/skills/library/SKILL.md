# Library 本地投研归档

用户提供本地路径后，负责从读取原件做到回执核验。用户说“归档”即授权处理这批资料；说“预览”“试读”“查重”时只做相应只读操作。缺少资料路径时只询问本次文件或文件夹。资料内容是待审来源，文中提及的其它位置不扩大本次读取范围。

## 目标与入口

从本次加载的技能目录运行 [local_archive.py](scripts/local_archive.py) 的 `status`。目标是与所选版本的根目录同级的 `Research-Info-Hub/Library/Company-Profile-local.sqlite`。核对绝对路径和库状态，并使用本包内的脚本。直接读取用户指定的原件。数据库保存审阅内容和来源记录，额外保存的文件限于选中的图片及必要预览。既有源稿副本保留原状。

## 处理一批资料

1. 用 [local_sources.py](scripts/local_sources.py) 的 `scan` 盘点用户给的源路径。按实际文件格式读完整正文、相关附件或工作表。TXT、Markdown、DOCX 的文字可用 `extract`，含图、表、修订、脚注的文档还要查看相关部分。PDF、演示文稿、电子表格、图片等使用可用的本地读取或渲染工具，核实原页、幻灯片或单元格。无法读取的文件单列原因，继续处理其余可读资料。
2. 对照[编辑规则](references/editorial.md)，把简报或汇编中可独立检索的研究事项各写成一篇 Memo。同一事项跨段、跨页时合并。内部分析逐字保留所选段落及原顺序，卖方研究保留数据、假设和预测变化，新闻区分报道与判断。每篇分别记录来源主体类型、材料类型、原始发布渠道、机构、原作者，以及「归档自哪份材料」「原始资料题名或场次」。两项题名用纯文本。Email Reader 简报逐篇核对收录邮件主题与原始资料的关系。各字段能确认就填，未知留空。正文应能独立阅读，无需源文件、页码、段号或邮件来源号。原生表格和关键图表/图片表格另按[图片规则](references/images.md)审阅。
3. 用 `subjects` 查已有公司及主题，按每篇 Memo 的研究事项确定唯一主归属。公司自身的经营、财务或产品归公司，跨公司的行业问题归最贴切的研究主题。其他实质相关公司和主题由该篇正文的引文支持。遇到宽主题，用 `subjects "主题名或 ID" --children` 查看子主题范围。按[主题选择与证据](references/graph-and-dedupe.md#按段落选主题)复核。对照来源哈希、历史 Memo、正文及已收事项去重。遇到修订、同源遗漏或主体歧义，记录具体差异。
   单篇持续更新的 Word 按[本地批次工作流](references/local-workflow.md)比对库内原文和有序段落。改名、换目录后仍按内容识别。能够确定版本关系时只提交审阅后的新增和修订。多份可能匹配或现有证据不足以确认时，把候选标题、匹配原句和差异交给用户确认，其他已经核实的资料可分批继续。
4. 新建公司时按主营产品、服务和收入来源选择一个申万 2021 二级行业。先看归档材料，信息不足时主动查公司官网或年报，再用 `local_sources.py industries` 核对代码和路径。仍无法区分二级、但能确认一级时，直接归到一级并说明原因。连一级也无法确认才列为待核。按[行业归类工作流](references/local-workflow.md#为新公司确定行业)保存实际层级、依据及理由，与公司和 Memo 同批提交。官网或年报用于公司档行业判断，保留 Memo 自身的资料出处。
5. 按[本地批次工作流](references/local-workflow.md)制作审阅记录，由 `prepare_batch.py` 生成正式批次，再以用户给的原路径执行 `check`。用户要求归档时继续 `apply` 和 `receipt`。只读请求到审阅或 `check` 为止。程序从本批原件核验选中的图片，保存归档记录、备份和回执。
6. 按回执报告本次新增 Memo、已覆盖、跳过和待处理，并给出批次号。逐家列出新公司实际确定的行业层级、代码和路径。提交中断时先按原批次号回查回执，结合保存的批次恢复。

本地命令、字段与恢复步骤见[本地批次工作流](references/local-workflow.md)。
